# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added
- **Free-form `collection_type` with suggestions (COL-001)** — `create.php`/`edit.php` replace the fixed collection-type dropdown with a free-text field backed by a `<datalist>` (`CollectionController::collectionTypeSuggestions()`) listing the 5 starter presets plus any custom type already in use, so a new collection can adopt any type name without touching code. Fixed a real bug found along the way: `CollectionController::update()` always overwrote the posted `collection_type` with the API's current value, so the field could never actually be changed through the edit form.
- **Editable entry CTA label per collection (COL-002)** — new `entry_cta_label` per-language field in "Detalles de la colección", consumed by the public web app's collection listing instead of a hardcoded `news`/`portfolio` label. Fixed a real bug found along the way: `CollectionStoreRequest::normalizeTranslations()` rebuilds each translation row from an explicit field list, so the new field rendered in the form but was silently dropped before reaching the API until added to that list.
- **`CmsPresetCatalog` degrades block presets per-block instead of all-or-nothing (COL-003)** — `filterAvailablePresets()` now keeps a preset with just the blocks that exist in the active block catalog (previously a single missing block type hid the whole preset with no explanation); presets report their dropped block keys via a new `missing_blocks` field, and the Wizard's structure step shows an explanatory message when a preset is partial.
- **Wizard steps editor for collection structure (WIZ-STEPS-EDITOR-01)** — new "Pasos del asistente" tab in `block_template_editor.php` (`collectionBlockTemplateBuilder` Alpine component) lets admins arrange which native entry fields (`title`, `excerpt`, `featured_image`, `meta_title`, `meta_description`, `og_image`) the "Add content" wizard asks for and how they're grouped into steps — add/remove/reorder steps, add/remove fields from the fixed catalog, toggle `required` per field, with a non-blocking warning when `title` is missing from every step. `entryPublish.js` gains dual-mode `og_image` support (matching `featured_image`) and excludes the three new native keys from `wizard_extra` duplication. Backed by the domain's new `WizardConfigValidator`, which rejects any field key outside the fixed catalog server-side.
- **Per-language translation badges on block instance views** — `BlockInstanceController::index/children`, `EntryController::show`, and `PageController::show` now render per-language completion pills for every block via the domain's new `GET /cms/translations/audit/owner/{ownerType}/{ownerId}` endpoint (`TranslationAuditApiService::auditOwnerBlocks()`); new shared `components/table/block_translation_badges.php` partial (list/detail views) and a `TranslationStatus::badgeClasses($status, 'dot')` variant power per-language status dots on the block editor's language tabs. `BlockInstanceController::edit()` also gained `focus_lang` query param handling (already present on `PageController`/`EntryController`, missing here) so clicking a badge deep-links straight into the right tab.
- **Dual media selector on Entries and Pages** — `featured_image` (Entries) migrated from the file-only `translatable_image` component to the dual-mode `media_reference` (Hub file or external URL); new `og_image` dual-mode field added to both Entries and Pages create/edit forms (previously not exposed anywhere in the admin despite domain support); `EntryStoreRequest`/`PageStoreRequest::normalizeTranslations()` rewritten to read the nested `{source_kind, file_id, url}` object; `langTabs.js`'s copy-to-other-languages mechanism generalized from a `block_data`-only pattern to any `[fieldKey][...]` suffix match; the entry-level image field on the Wizard's base step screen is now dual-mode as well
- **Dashboard redesign** — `DashboardController` and `dashboard/index.php` replaced the generic activity feed with four widgets: translation coverage by language (`widgetTranslations`), a full permission-aware summary grid covering CMS resource counts plus form submissions total and a pending-review badge (`widgetSummary`), and recent CMS activity across pages and entries (`widgetCmsActivity`); each widget is permission-gated and cached (60–300s) via `safeApiCall()`, and health/uptime/user/file stats moved to a secondary sidebar and closing stats row. An initial separate "needs attention" widget (`widgetAttention`) was folded into the summary widget the same day: its only signal (pending translations) duplicated the dedicated translations widget, while form submissions gained their own real total instead of being hidden inside it. The sidebar's Quick Start widget was later replaced with `widgetAnalytics()`, a 7-day traffic snapshot (views, unique visitors, top page, top referrer) backed by the same `AnalyticsApiService::overview()` endpoint used by the Analytics page's KPI cards, cached 300s and gated by `cms.analytics.read`. Service Health rows (`health_card.php`) are now individually collapsible per app instead of auto-expanding, so a service needing attention still surfaces via its pulsing status dot without forcing the detail panel open
- **Enhanced block preview system with document and multimedia block types** — added preview views for document_download, document_gallery, pdf_viewer, and video_gallery blocks; improved `form_helper.php` normalize_media_reference_value() to handle multiple field name variations (camelCase, snake_case, external_url, file_url); added preview_mode parameter to BlockPreviewController for sample/live preview toggling; enhanced blockPreview.js to manage preview modes transparently
- **Reusable media reference field component** — new `media_reference.php` component and `mediaReferenceField.js` Alpine.js component for unified handling of media selection across blocks; supports both Hub-managed files and external URLs with automatic source detection; includes preview, source toggling, file picker integration, and copy-to-all-languages support; replaces ad-hoc media handling in block forms with standardized, reusable UI
- **Menu item create/edit views** — full CRUD interface for menu items with create and edit forms supporting link configuration, label, and sorting; integrated with MenuApiService for item creation and update workflows
- **Automatic translation for block instances** — block creation now supports automatic translation of block content across all active languages via "Translate All" button and per-file copy-to-languages feature; language context (default language code and ID) passed to the UI for seamless multilingual block management.
- **Exception handling for unavailable services** — `PermissionsSessionRefresher` and `BlockCatalogService` now gracefully handle timeouts and connection errors when Hub or Domain APIs are unavailable; permission refresh and block catalog loading log warnings and continue gracefully instead of crashing, improving admin resilience during infrastructure incidents.
- **Block catalog templates and filtering** — `BlockCatalogService` now provides `templates()` and `selectableForEntries()` methods for retrieving block type templates and filtering selectable blocks (excluding container-only types)
- **Site identity translation panel** — new `cms_settings_build_translation_panel()` helper and `translatable_settings_panel` component for managing multilingual site settings across active languages
- **Automatic translation for menu items** — menu item create/edit forms now support a "Translate All" button covering `label` and `custom_url`; `BaseWebController::buildTranslateTargets()` gained a `$keyByLanguageId` parameter so translate targets can be keyed by real language id for forms (like menu items) whose inputs are named by language id instead of array position
- **Per-language menu name translations** — menu create/edit forms now include a language-tabbed `translations` panel (new `cms/menus/_translations.php` partial) so each menu's `name` can be localized per active language; `MenuStoreRequest` normalizes and validates the submitted `translations` rows, dropping blanks for non-default languages
- **Translation status badges across CMS list tables** — new shared `components/table/translation_badges` view component renders per-language completion badges (complete/incomplete/missing) on the Pages, Entries, Collections, Categories, Tags, Forms, Menus, and Settings index tables; clicking a badge deep-links into the edit form with `?focus_lang={id}` so editors land directly on the language tab that needs attention

### Changed
- **Global submit guard** — replaced the per-form `submitting_overlay` Alpine component (duplicated `x-data`/`@submit.prevent` boilerplate on every mutating form) with a single global submit guard in `app.js`; it disables page controls and shows a blocking overlay on any `POST`/`PUT`/`PATCH`/`DELETE` form submission or fetch/XHR call, including Alpine-driven async submits, without per-view wiring
- **CMS page types** — `CmsPresetCatalog::pageTypes()` and the pages index filter dropped the editorial `about`, `history`, and `events` presets in favor of the domain's narrowed `page_type` enum (those distinctions now live in page content and slug); the `page_type_*` language keys for the removed presets (plus `components`, `media`, `portfolio`) stay in `Pages.php` so existing pages seeded with those values before the domain migration still render a readable label instead of a blank string

### Fixed
- **`MenuController` silently swallowed upstream failures** — its 4 option-loading helpers (`getLanguages`, `pagesOptions`, `entriesOptions`, `collectionsOptions`) were the only ones of 7 sibling controllers that didn't call `maybeFlashDevError()`, so a failing `languageApiService`/`pageApiService`/`entryService` call while opening the menu item form rendered empty dropdowns with no error signal even in development. Also fixed a latent, unrelated bug found while writing the regression test: `cms/menus/items/create.php` and `edit.php` declared their `buildParentOptions*()` helper as a top-level PHP function with no `function_exists()` guard, which fatals with "Cannot redeclare" if the view renders twice in the same PHP process (never happens in production, but breaks any test suite that hits the view more than once per run)
- **`TagStoreRequest` submitted blank optional-language translation rows** — unlike `CategoryStoreRequest` and the other CMS Request DTOs, `TagStoreRequest::payload()` built its `translations` array by hand and only checked `language_id`, not whether `name`/`slug` had content; a language tab left blank when creating or editing a Tag was sent to the API as a real translation. Now uses `TranslationRowNormalizer` with the same content check as `CategoryStoreRequest`
- **Collection structure save button** — the save button on `/admin/cms/collections/{id}/structure` was labeled "Administrar estructura" (a leftover from the entry point that opens the screen), which read as a link rather than a submit action; relabeled to "Guardar estructura"/"Save structure", added a stable `data-testid="collection-structure-save"` for tests, and moved the actions sidebar to the top of the stack on mobile (`order-first`/`lg:order-none`) so the save action isn't buried below the structure editor on small screens
- **Wizard content flow: unified steps and missing image field on required blocks** — the Wizard's "Agregar contenido" flow ran two independent progress bars (native fields, then block fields) and its "Imagen del Proyecto" block, marked required, never exposed an image field at all — only "Texto Alternativo"/"Pie de Foto" — letting editors "complete" a required image block without picking any image. Root cause: `entryPublish.js::blockContentFieldsFor()` only read `block_types[key].fields`, never `config_fields`, where `media_reference` fields actually live. Fixed by reading `config_fields` the same way `blocks.js::blockFields()` already did, routing `source:'config'` values into `block_config` via a new `buildBlockContentConfig()` (previously only `translations` was sent, so a captured `media_reference` value could never have been persisted), and merging native + block steps into one progress bar (`navigation.js`: `totalUnifiedSteps`/`unifiedProgressPercent()`). All five collection presets (`CmsPresetCatalog`) now combine title+excerpt into one step and add a dedicated featured-image step
- **Dashboard forms count** — the "Formularios Dinámicos" summary card showed `0` despite forms existing; the domain's `/cms/forms` endpoint ignores pagination filters and always returns a flat array with no `meta.total`, which the generic `extractTotal()` helper couldn't find. Forms now has its own block in `widgetSummary()` that counts the response array directly via `extractItems()`
- **CMS Settings detail view** — `SettingController::show()` now loads active languages and passes them to the view, fixing a silent failure where the translation status panel never rendered on `/admin/cms/settings/{id}`; also deduplicated the six inline `languageApiService->list()` calls across `SettingController` into a shared `getLanguages()` helper and extracted the seven near-identical `$copyMappings` blocks across CMS edit views into `cms_translation_copy_mappings()`
- **`RateLimitFilter`** — `GET`/`HEAD`/`OPTIONS` requests no longer consume the shared write-throttle budget, so normal Admin navigation and page loads (which fire several reads at once) can no longer trip the limit; thresholds are now configurable via `ADMIN_RATE_LIMIT_REQUESTS`/`ADMIN_RATE_LIMIT_WINDOW`, and the CMS translate route (external DeepL call) now opts into an explicit `ratelimit:300,60` since it is no longer covered by the default
- **Improved API error debugging in development** — enhanced `BaseWebController` with `flashDevError()` and `renderDevApiErrorPanel()` methods for standardized error snapshot storage; the dev error panel (`dev_api_error_panel.php`) now displays normalized API failures with exact HTTP status, request body, field errors, and messages; accessible on read-only screens (dashboard, metrics, analytics) without requiring a form submission
- **CMS validation consistency** — all CMS Request DTOs now normalize empty translation rows before validation, preventing spurious validation errors on optional blank language tabs; updated validation messages for consistency across store/update forms
- **Media reference field URL persistence on source switching** — when toggling between hub file and external URL sources, the media reference field now preserves visible URLs as fallbacks instead of clearing them; added `_visibleReferenceFallback()` to maintain visual continuity across source changes, preventing data loss when switching between file library and external URL modes
- **Form translation field indexing** — form submission now uses sequential array indices (`translations[0]`, `translations[1]`, …) instead of language IDs (`translations[language_id]`) to ensure proper form data serialization and backend processing; `FormController` now intelligently resolves `language_id` from either the field name or the nested data, ensuring backward compatibility and correct translation grouping regardless of input structure.
- **Form field validation styling** — all form inputs in create and edit forms now use `input_class()` helper to apply dynamic validation error styling (red border on failed validation), improving visual feedback for users when form submission errors occur; applied to form key, notification email, and all multilingual translation fields.
- **Lucide icon rendering in dynamic form options** — when adding or removing field options in the form builder, icons on dynamically created rows would remain unrendered (raw `<i data-lucide>` markup) until the field was saved. Now properly re-scans DOM for new Lucide markup via `$nextTick()` after option add/remove/edit operations, ensuring icons render immediately. Also improved visual feedback for missing option labels in languages other than the default (displays in amber instead of gray).
- **`ApiClient`** — only retry `GET`/`HEAD` requests on 5xx responses; write requests (`POST`/`PUT`/`DELETE`) now fail within the configured timeout instead of being retried, which could multiply latency past `max_execution_time` while a user was saving a form
- **Site identity save flow** — `SiteIdentityController` now only sends the settings that actually changed (via a new `SettingApiService::batchUpdate()`) instead of overwriting every field on every save, preventing a stale unrelated field from blocking the whole save; the update form no longer overwrites a setting with an empty value when a metadata-driven control omits its field from the POST body; the identity load view also routes through `safeApiCall()`/`failApi()` so upstream failures surface the dev error panel instead of failing silently
- **Default-language translation badges marked as missing** — `translationStatus()` in `remoteTable.js` validated the default language against `row.translations` only, but the API returns the default language's content in the row's own base fields (e.g. `setting_value`), not as a translation row; the badge component now passes an `is_default` flag per language so the default language is validated against `row` directly
- **`pagecache` filter served stale responses** — removed the `pagecache` entry from `app/Config/Filters.php`'s `aliases` and `before`/`after` pipelines; CI4's page cache was serving cached HTML for endpoints whose data had already changed.
- **`BlockTypeOptionsResolver` missed config fields present only in `schema_definition`** — some domain API responses project `config_fields` at the top level of the block type payload while leaving the canonical field set in `schema_definition.config_fields`; a partial top-level projection could hide fields (e.g. hero slider's `transition`) that existed in the schema. The resolver now merges `schema_definition.config_fields` and the top-level `config_fields` before resolving dynamic options, so the schema's fields always win over an incomplete projection.

### Changed
- **Content Security Policy (CSP) headers** — added conservative CSP headers to admin panel for enhanced security; restricts inline scripts, external stylesheets to allowlist, and frames to same-origin only; enables CSRF token injection protection via CSP nonce mechanism
- **Category form and reorder UI** — removed `sort_order` field from category form (order managed via reorder interface); enhanced reorder view to display category names with subtitles showing collection and parent category labels for improved relational context
- **Confirm modal — accepting state with spinner** — `$store.confirm.accept()` now sets `accepting: true` before calling the callback; the "Confirmar" button shows an animated spinner and is disabled while accepting; backdrop and Escape key blocked during action; 5-second safety timeout auto-closes if navigation does not occur (`app.js`, `confirm_modal.php`)
- **Destructive confirmations — 4 views migrated to modal pattern** — `cms/pages/blocks/index.php`, `cms/pages/blocks/children/index.php`, `cms/menus/show.php`, and `admin/universal/index.php` replaced native `onsubmit="return confirm()"` with `@submit.prevent="$store.confirm.show(...)"` using the exact resource name
- **Role-permissions matrix — orientation and change tracking** — added a per-role orientation callout with reactive permissions counter (`selectedCount`) updated on every checkbox change; `isDirty` flag shows "Tienes cambios sin guardar" warning next to the save button; new language keys `role_permissions_hint`, `role_permissions_selected_label`, `unsaved_changes` added in `es`/`en` (`Iam.php`, `App.php`)

- **Applications index — read-only clarity** — removed duplicate subtitle text; `empty_state` now uses `Iam.applications_empty` and `Iam.applications_managed_server_side` as title/description instead of generic defaults

### Fixed

- **File deletion protection** — admin now prevents deletion of files with active references (used by pages, blocks, collections); displays user-friendly error messages and bulk operation feedback when deletion is blocked due to active usage
