Acceso y reglas base

El primer detalle importante es entrar siempre por el mismo host que usa el proyecto.

Usa exactamente esta URL
http://localhost:8182/login. No reemplaces localhost por 127.0.0.1 en el navegador: la sesión y el CSRF están ligados al host.

Credenciales iniciales de desarrollo

Correo: admin@example.com
Contraseña: ChangeMe123!

Son las credenciales del README raíz. Cámbialas o reemplázalas antes de cualquier uso real.

Qué hay en la pantalla

Campos Correo y Password, botón Ingresar, recuperación de contraseña y enlace para crear una cuenta.

  1. Abre el enlace de login en una pestaña nueva.
  2. Escribe el correo y la contraseña. No guardes credenciales de desarrollo en un equipo compartido.
  3. Pulsa Ingresar y espera el Escritorio.
  4. Si olvidaste la contraseña, entra en ¿Olvidaste tu contraseña?; si todavía no existe una cuenta, usa Crear una cuenta.
No ignores un 403
Un error CSRF/403 después de entrar suele significar que mezclaste hosts. Cierra esa pestaña y vuelve a abrir http://localhost:8182/login.
01

Cómo leer el panel

La interfaz se repite de forma consistente. Aprender una lista y un formulario te permite moverte por casi todo el CMS.

Barra lateral

Abre Menú para mostrar u ocultar la navegación. Los módulos están agrupados en Administración, Identidad y Accesos, CMS, Contenido, Estructura y Configuración.

Barra superior

Muestra el nombre de la pantalla, el idioma visible (ES / EN) y el menú de la cuenta (Mi perfil / Cerrar sesión).

Listas

Usan búsqueda, filtros, columnas ordenables, botones de página y acciones de Ver, Editar o Eliminar.

Patrón de trabajo en una lista

  1. Filtra por texto, estado, colección, idioma o grupo según la pantalla.
  2. Usa Buscar. Para volver al estado inicial, pulsa Limpiar filtros.
  3. Haz clic en el encabezado de una columna con flechas para ordenar.
  4. Abre Ver para consultar sin editar, o Editar para cambiar datos.
  5. Confirma cualquier acción destructiva en el diálogo; si no estás seguro, vuelve atrás.
IndicadorQué significaQué hacer
Activo / PublicadoEl registro puede usarse o mostrarse según el módulo.Verifica traducciones, enlaces y vista previa antes de publicarlo.
BorradorEl contenido está guardado pero no es público.Continúa editando o publícalo cuando la revisión esté completa.
FaltanteExiste una traducción o campo requerido sin completar.Abre la acción Traducir desde la auditoría.

03

Perfil y archivos

La cuenta controla tus datos; Archivos controla la biblioteca que luego reutilizan páginas, entradas y bloques.

Perfil

Foto de perfil

Subir foto abre el selector de archivos. Usa una imagen pequeña y profesional.

Información personal

Edita nombre y apellido con Guardar cambios. Revisa el correo mostrado antes de usarlo como identidad operativa.

Seguridad

La pantalla ofrece Enviar enlace de reset para iniciar un restablecimiento de contraseña.

Verificación de correo

Si la cuenta no está verificada, usa Reenviar verificación. Verifica que el correo de destino sea correcto.

Archivos

  1. En Archivos, selecciona el archivo en Subir Nuevo Archivo y pulsa Subir Archivo.
  2. Filtra por texto, categoría (Imágenes, Documentos, Video, Audio), fechas o tamaño.
  3. En la tabla, abre Ver para consultar el detalle, o Descargar para obtener el original.
  4. En el detalle, revisa las variantes generadas —sus dimensiones dependen del archivo y de la configuración— y guarda texto alternativo, pie y crédito.
  5. Consulta Usado en antes de eliminar. Si el archivo está referenciado, corrige primero esas referencias.
Buenas prácticas editoriales
Completa siempre el Texto alternativo; describe la imagen para lectores de pantalla y SEO. Usa nombres de archivo estables y evita subir duplicados.

Papelera

La Papelera permite filtrar archivos enviados allí y ofrece Restaurar o Eliminar definitivamente. La segunda acción borra el archivo del disco y es irreversible: úsala solo tras confirmar que no hay usos.

04

Administración

Estas pantallas controlan quién entra, qué ocurrió y cómo está funcionando la plataforma.

Usuarios

La lista muestra nombre, email, estado y fecha de creación. Usa Crear usuario para abrir el formulario.

Crear / editar

Nombre, apellido y email son obligatorios. Elige uno o más roles: admin, cms-admin, cms-editor, superadmin o user.

Detalle

Consulta roles y acciones rápidas: editar, administrar roles, ver auditoría o eliminar. Elimina solo cuentas que ya no deban conservar acceso.

Regla de roles
Si dejas los roles vacíos, el sistema asigna user por defecto. Si quitas todos los roles de un usuario existente, vuelve a aplicar ese rol base.

Auditoría

Registra operaciones con ID, usuario, acción, entidad, IP, fecha y resultado. Filtra por texto, acción, usuario, resultado y severidad. Ver abre el detalle del evento.

API Keys

La lista muestra nombre, prefijo, estado, límite de peticiones, ventana y fecha. En Nueva API key define nombre, límite total, ventana, límite por usuario y límite por IP. En edición puedes cambiar nombre, estado y límites; el detalle permite editar o eliminar/revocar.

Trata una API key como una contraseña
No la pegues en tickets, capturas ni repositorios. Si sospechas una filtración, desactívala o elimínala y genera una nueva.

Métricas y Salud

Elige un Period y pulsa Aplicar Filtros. Revisa peticiones totales, tiempo promedio, disponibilidad, peticiones exitosas, tendencias y tabla SLO.

Analytics

Elige el período para revisar visitas, visitantes únicos, páginas más visitadas, referrers y dispositivos. Úsalo para priorizar contenido, no para modificarlo.

05

Identidad y accesos

Esta zona define las capacidades de cada persona y de cada aplicación.

Roles

Un rol tiene Aplicación, Código, Nombre, Descripción y un conjunto de permisos. En una edición, al guardar se reemplaza el conjunto completo: marca todo lo que debe conservarse.

Roles × permisos

Es la matriz de asignación masiva. Selecciona un rol, revisa los permisos agrupados por aplicación y recurso, usa Seleccionar todo o Ninguno dentro del grupo cuando corresponda, y pulsa Guardar. La pantalla avisa Tienes cambios sin guardar mientras exista una modificación local.

NivelEjemploQué permite
READcms.pages.readConsultar páginas.
WRITEcms.pages.writeCrear o editar páginas.
ADMINcms.pages.adminAdministrar por completo el recurso, incluyendo operaciones sensibles.
SUPERADMIN-ACCESSiam.superadmin-accessOperaciones reservadas de superadministración.

Permisos

Crear o editar un permiso requiere Aplicación, Código, Recurso, Acción y una descripción opcional. Mantén la convención de códigos: por ejemplo users.write, entries.read.

Aplicaciones

Es una pantalla de solo lectura. Muestra código, nombre, estado y fecha. Las aplicaciones se registran del lado del servidor mediante php spark apps:bootstrap; no intentes crearlas desde este panel.

06

Flujo recomendado del CMS

Para un sitio nuevo, los asistentes reducen errores de estructura y te llevan por el orden correcto.

1 · BaseAsistente de estructura

Crea colección, página o menú.

2 · ModeloColecciones

Define flags, traducciones y bloques.

3 · DiseñoPáginas y bloques

Arma la composición visual.

4 · DatosEntradas

Carga contenido por idioma.

5 · RevisiónAuditoría + preview

Corrige faltantes y publica.

Asistente de estructura

  1. Elige Crear colección, Crear página o Crear menú nuevo.
  2. Para una colección, selecciona preset Blog, Noticias, Portafolio, Servicios u Otro, o crea sin preset.
  3. Completa nombre visible y slug base; revisa las propuestas para los idiomas activos. En esta instalación, el segundo idioma observado es EN.
  4. Usa Anterior y Siguiente para revisar; pulsa la acción de crear solo cuando el resumen sea correcto.
  5. Después del éxito puedes crear la primera entrada, abrir el detalle o volver a colecciones.

Asistente de contenido

Permite Agregar contenido, Editar una página o Editar enlaces del menú. El flujo conserva borradores, muestra traducciones automáticas y termina en una pantalla de revisión antes de Publicar ahora.

No confundas asistentes con publicación automática
El asistente puede preparar traducciones y contenido base, pero revisa títulos, slugs, bloques y enlaces antes de publicar. Si un bloque no se guardó, usa Terminar de editar bloques.
07

Contenido

Aquí se administra la información editorial y las entidades que la organizan.

Colecciones

Una colección define el tipo de contenido (por ejemplo noticias o portafolio). La lista muestra clave, traducciones, estado, aprobación, categorías, etiquetas y fecha.

  1. Pulsa Nueva Colección.
  2. Completa nombre y slug por idioma, clave interna, tipo de colección y descripción.
  3. Marca Está Activo y, si aplica, Requiere Aprobación, Habilita Categorías y Habilita Etiquetas.
  4. Define orden, prioridad y frecuencia por defecto del sitemap.
  5. En el detalle, usa Administrar estructura para configurar bloques heredados y pasos del wizard.

Entradas

Zona de la capturaQué comprobar
Datos baseColección, estado y destacado determinan dónde y cómo se mostrará.
Pestañas de idiomaES es la base; cada idioma activo tiene sus propios textos, slug, SEO e imagen.
ClasificaciónCategorías y etiquetas permiten que los listados filtren la entrada.
Plantilla/bloquesUna colección puede heredar bloques fijos; no los elimines sin saber qué parte pública alimentan.
Acciones finalesGuarda borrador, previsualiza y publica/programa solo tras revisar la lista de publicación.
  1. En Nueva Entrada, elige Colección y Estado; decide si es Destacado.
  2. Para ES, EN y cualquier otro idioma activo completa título, slug, extracto, imagen destacada, meta título, meta descripción e imagen Open Graph. ES es el idioma base indicado con una estrella.
  3. Selecciona categorías de la colección y etiquetas globales cuando estén disponibles.
  4. Define orden, fecha de publicación, fecha programada, inclusión en sitemap, prioridad y frecuencia de cambio.
  5. Guarda como borrador mientras trabajas. En edición, si la colección tiene plantilla fija, administra esos bloques desde Gestionar Bloques.
Imágenes: biblioteca o URL externa
Usa Biblioteca para reutilizar un archivo del Hub o URL externa para un enlace público directo. Prefiere la biblioteca para mantener variantes, metadata y trazabilidad centralizadas.

Categorías y etiquetas

Las categorías pertenecen a una colección y pueden tener una Categoría Principal para construir jerarquías. Las etiquetas se reutilizan entre colecciones. En ambos casos, completa nombres y slugs por idioma y activa el registro cuando corresponda. Usa Reordenar en categorías si necesitas cambiar el orden.

Formularios dinámicos

En Nuevo Formulario define clave única, activo, CAPTCHA, email de notificación, respuesta automática y la clave del campo email. En las pestañas de idioma completa nombre, texto del botón, descripción y mensajes.

En edición aparece el Constructor de Campos: agrega clave, tipo, opciones, obligatorio, activo, etiqueta, placeholder, ayuda y etiquetas traducidas. Guarda el formulario antes de usarlo en un bloque.

Envíos

Filtra por Todos, Nuevo, Leído, Respondido, Spam o Archivado. Si no hay registros activos, la tabla muestra “No se encontraron resultados”; eso no es un error.

08

Estructura

La estructura conecta páginas, navegación y bloques visuales.

Páginas

En Nueva Página selecciona tipo funcional (Inicio, Genérica, Contacto, Privacidad, Términos, 404, 500, Mantenimiento o Índice de Colección), estado, colección, página padre y orden.

Luego completa por idioma título, slug, extracto, meta título, meta descripción e imagen Open Graph. En publicación define fechas, sitemap, prioridad y frecuencia. En edición aparece Administrar Bloques; usa Reordenar desde la lista para ordenar páginas.

Bloques de una página

Zona de la capturaQué hace
OrdenSubir/Bajar cambia el orden visual; después usa Guardar Orden si aparece.
ContenedorSlides, Items o Hijos abre el nivel interno del bloque.
EditarAbre los campos que el esquema del tipo define; no todos los bloques tienen los mismos controles.
Vista previaPermite comprobar la salida del bloque sin publicarlo todavía.
EliminarRetira la instancia de la página; confirma dependencias antes de aceptar.
  1. Pulsa Añadir Bloque y elige un tipo del catálogo: hero, texto enriquecido, imagen, CTA, galería, formulario, video, métricas, FAQ y otros.
  2. Completa la configuración del diseño y el contenido por idioma. Revisa el indicador Activo / Visible.
  3. Guarda con Añadir Bloque o Actualizar Bloque; abre Vista previa cuando esté disponible.
  4. En la lista usa Subir, Bajar y después Guardar Orden. Los contenedores tienen enlaces como Slides para editar hijos.

Menús

Un menú tiene nombres traducidos, Clave del menú, Ubicación (por ejemplo header, footer o footer_secondary) y estado activo.

En Nuevo elemento del menú puedes usar el ayudante de categoría para construir una URL; definir etiqueta y URL por idioma; elegir tipo de enlace (página, entrada, listado de colección, URL personalizada o sin enlace); seleccionar padre, destino, icono Lucide, clase CSS y activo. La categoría no es un tipo de enlace independiente. Usa Reordenar para ajustar jerarquía y posición.

Un enlace visible no es contenido
Crear o editar un elemento del menú solo cambia navegación. La página, entrada o colección de destino debe existir, estar activa y tener la traducción correspondiente.

Administración, observabilidad y acceso

4. Usuarios

Navegación: Usuarios.

Objetivo: crear cuentas y asignarles el mínimo de roles necesario.

Campos: nombre, apellido, email, estado y roles. Roles observados: admin, cms-admin, cms-editor, superadmin y user. El detalle ofrece Ver, Editar, Administrar roles, Auditoría y Eliminar.

Comportamiento: si los roles quedan vacíos al crear, se asigna user; si se quitan todos en una cuenta existente, vuelve a aplicarse ese rol base.

5. Auditoría

Navegación: Auditoría.

Objetivo: reconstruir quién hizo qué, cuándo y desde dónde.

Columnas: ID, usuario, acción, entidad, IP, fecha, resultado y severidad. Filtros: texto, acción, usuario, resultado y severidad. Ver abre el detalle del evento. No borres eventos durante una investigación.

7. Métricas / Salud

Navegación: Métricas.

Objetivo: verificar disponibilidad y desempeño del API.

El selector Period y Aplicar Filtros actualizan peticiones totales, tiempo promedio, disponibilidad, peticiones exitosas, tendencias y tabla SLO. Las alternativas del período dependen de la instancia; compara períodos equivalentes y no solo el valor actual.

8. Analytics

Navegación: Analytics.

Objetivo: entender el uso del sitio público para priorizar mejoras.

El período actualiza visitas, visitantes únicos, páginas más visitadas, referrers y dispositivos. Estos datos orientan decisiones; no publican contenido ni convierten una página en destacada.

Campos: aplicación, código, recurso, acción y descripción opcional. Ejemplos de convención: cms.pages.read, users.write. No elimines ni renombres un permiso en uso sin revisar roles dependientes.

16. Colecciones

Navegación: Colecciones.

Campos: nombre y slug por idioma, clave interna, tipo, descripción, activo, requiere aprobación, habilita categorías, habilita etiquetas, orden y valores por defecto de prioridad/frecuencia del sitemap. Administrar estructura configura bloques heredados y pasos del wizard.

La clave es una referencia técnica estable; cambiarla puede afectar entradas, URLs e integraciones.

17. Categorías

Navegación: Categorías.

Selecciona colección, categoría principal/padre, nombre y slug por idioma y estado activo. Reordenar cambia la posición. Revisa entradas asociadas antes de eliminar.

18. Etiquetas

Navegación: Etiquetas.

Completa nombre y slug por idioma y marca activo. Son reutilizables entre colecciones y no tienen jerarquía padre/hijo. Evita sinónimos que fragmenten los listados.

19. Formularios Dinámicos

Navegación: Formularios Dinámicos.

Formulario: clave única, activo, CAPTCHA, email de notificación, respuesta automática, clave del campo email y textos por idioma (nombre, descripción, botón y mensajes). Campo: clave, tipo, opciones, obligatorio, activo, etiqueta, placeholder, ayuda y etiquetas traducidas.

Flujo: configurar → definir campos → guardar → probar un envío → revisar Envíos → insertar en página/bloque.

20. Envíos

Navegación: Envíos.

Las pestañas observadas son Todos, Nuevo, Leído, Respondido, Spam y Archivado. Si una pestaña está vacía, “No se encontraron resultados” es un estado normal, no un error de formulario.

Páginas, menús y bloques

21. Páginas

Navegación: Páginas.

Campos: tipo (Inicio, Genérica, Contacto, Privacidad, Términos, 404, 500, Mantenimiento o Índice de Colección), estado, colección, padre, orden; por idioma título, slug, extracto, meta título, meta descripción y Open Graph; fechas y sitemap. Administrar Bloques abre la composición y Reordenar ordena el árbol/listado.

22. Menús

Navegación: Menús.

Menú: nombres por idioma, clave, ubicación (header/footer/footer_secondary) y activo. Ítem: etiqueta y URL por idioma, tipo de enlace (página, entrada, listado de colección, URL personalizada o sin enlace), padre, destino, icono Lucide, clase CSS y activo. Hay un ayudante para construir URLs de categoría, además de reordenar y guardar orden; categoría no es un tipo de enlace separado.

Prueba cada destino en cada idioma: un ítem activo no arregla una página inexistente.

23. Tipos de Bloque

Navegación: Tipos de Bloque.

Campos: clave, nombre, categoría, descripción, icono, esquema JSON, campos traducibles, campos de configuración, soporte para páginas/entradas, contenedor, hijos permitidos, activo y orden. Refrescar caché actualiza el catálogo.

Los campos de una instancia dependen del esquema JSON. No cambies una clave usada sin planificar migración: las instancias guardan esa referencia.

Configuración global y traducciones

24. Redirecciones

Navegación: Redirecciones.

Campos: ruta anterior (empieza con /), nueva URL, nota, tipo 301 o 302 y activo. Acciones: importar/exportar CSV. Valida rutas, duplicados y bucles antes de activar.

25. Idiomas

Navegación: Idiomas.

Campos: código, nombre, nombre nativo, predeterminado, activo e idioma de reserva. Acciones: establecer como predeterminado y reordenar. Desactivar un idioma o cambiar el predeterminado es global; revisa auditoría y menús antes.

26. Auditoría de Traducciones

Navegación: Auditoría de Traducciones.

Filtros: búsqueda, idioma, recurso y estado. Audita páginas, menús, colecciones, entradas, categorías, etiquetas, formularios, campos, bloques, ítems de menú y configuración. Traducir abre el editor pendiente; Auto-traducir requiere revisión humana.

27. Identidad del sitio

Navegación: Identidad del sitio.

Grupos: nombre/título/tagline/descripción por idioma, contacto, emails, copyright, analytics, redes sociales, reCAPTCHA y diseño de menú de pie. En activos de marca selecciona logo y favicon desde la biblioteca. Traducir todos los idiomas, Auto-traducir y Guardar completan el flujo, pero revisa propuestas y dominio.

28. Configuración

Navegación: Configuración.

Filtra por clave, grupo o página. La lista muestra valor, tipo, grupo, si es traducible, traducciones y descripción. Ver consulta; Editar cambia. Crea una clave nueva solo después de confirmar qué código la consumirá y en qué formato.

Atajos por objetivo

Si no sabes qué módulo abrir, empieza por la tarea que quieres realizar.

Quiero crear una página informativa

Abre Receta A · página. Normalmente usarás Asistente de estructura → Crear página, luego Páginas → Administrar Bloques.

Quiero publicar una noticia o artículo

Primero verifica que exista una colección en Colecciones. Después sigue Receta B · entrada y revisa la lista de publicación.

Quiero agregar un formulario

Configura Formularios Dinámicos, define sus campos y luego inserta el bloque form_embed en una página. Consulta Receta D · formulario.

Quiero cambiar el menú

Abre Menús, edita el menú correcto (header o footer) y valida cada URL. Consulta Receta C · menú.

Quiero corregir traducciones

Abre Auditoría de Traducciones, filtra por idioma y recurso, pulsa Traducir y vuelve a revisar. La revisión antes de publicar incluye este paso.

Quiero dar acceso a otra persona

En Usuarios crea o edita la cuenta y asigna el rol mínimo. Antes de guardar, consulta la matriz de roles.

Regla para no perderse
El Admin separa tres preguntas: qué contenido existe (colecciones y entradas), cómo se muestra (páginas, menús y bloques) y quién puede cambiarlo (usuarios, roles y permisos). Si identificas cuál de las tres preguntas estás resolviendo, encontrarás el módulo correcto.

Mapa del sistema

Esta vista explica cómo se relacionan las pantallas y por qué algunas deben configurarse antes que otras.

1 · ModeloColección

Define qué tipo de entradas existen y qué campos o bloques heredan.

2 · RegistroEntrada

Es un artículo, servicio, proyecto o noticia dentro de una colección.

3 · ClasificaciónCategorías y etiquetas

Ordenan y filtran las entradas.

4 · PresentaciónPágina y bloques

Deciden la composición visual y los listados.

5 · NavegaciónMenú

Conecta al público con las URLs publicadas.

Ruta de una entrada

Colección → Entrada → Categorías/Etiquetas → Página índice o listado → Menú → Sitio público. Si falta cualquiera de los primeros pasos, el enlace final puede mostrar una lista vacía o una URL inexistente.

Ruta de un bloque

Tipo de Bloque → Instancia en una página o entrada → Contenido por idioma → Vista previa → Renderizado público. El tipo define qué campos aparecen; la instancia guarda los valores.

Ruta de un formulario

Formulario Dinámico → Campos → Bloque form_embed → Envío → Envíos. El formulario puede existir sin estar visible si ninguna página lo inserta.

Ruta de una traducción

Idioma base → Copiar o auto-traducir → Revisión humana → Auditoría → Publicación. Una traducción completa no garantiza que el enlace o la imagen también sean correctos en ese idioma.

Dependencia que suele causar errores
No empieces por el menú si todavía no existe la página o la colección que debe abrir. Crea primero el destino, prueba su URL y luego agrega el enlace.

Dependencias que cambian el formulario

Procedimientos completos para las tareas más comunes. Cada receta termina con una comprobación visible.

A · Crear una página informativa
  1. Abre Asistente de estructura y elige Crear página.
  2. Selecciona el tipo: Genérica para una página normal, Contacto si tendrá formulario, o el tipo legal/especial que corresponda.
  3. Escribe título y slug en ES. Revisa las propuestas para EN y los demás idiomas activos.
  4. Confirma el resumen y crea la página.
  5. Entra en Páginas → Administrar Bloques; añade, edita o reordena los bloques.
  6. Guarda como borrador, abre la vista previa si está disponible y revisa móvil, imágenes y enlaces.
  7. Completa traducciones, audita y publica solo cuando la URL pública esté probada.

Resultado esperado: la página aparece en Páginas con un estado claro y puede abrirse mediante su URL después de publicar.

B · Crear y publicar una entrada
  1. En Colecciones, identifica la colección correcta y confirma que esté activa.
  2. Abre Entradas → Nueva Entrada y selecciona la colección.
  3. Completa título, slug, extracto e imagen destacada en ES.
  4. Clasifica con categorías y etiquetas; marca Destacado solo si debe aparecer en espacios destacados.
  5. Define estado, fecha publicada o fecha programada y opciones de sitemap.
  6. Completa EN y cualquier otro idioma activo, o deja el contenido como borrador si todavía no está revisado.
  7. Administra bloques heredados o editables según la plantilla de la colección.
  8. Revisa la URL, SEO, imágenes, traducciones y página de listado; después publica o programa.

Resultado esperado: la entrada aparece en el listado público de su colección y el enlace individual funciona en los idiomas preparados.

C · Crear un menú y sus enlaces
  1. Abre Menús y elige el menú por su clave y ubicación, por ejemplo header, footer o footer_secondary.
  2. Verifica que el menú esté activo y que sus nombres traducidos estén completos.
  3. Pulsa Nuevo elemento y elige el tipo de enlace: página, entrada, listado de colección, URL personalizada o sin enlace.
  4. Selecciona el destino existente; para una categoría usa el ayudante y guarda el resultado como URL personalizada.
  5. Escribe la etiqueta por idioma, decide si abre en la misma pestaña y selecciona padre si será un submenú.
  6. Guarda el elemento, ordénalo y pulsa Guardar Orden si la pantalla lo solicita.
  7. Prueba el menú en ES, EN y cualquier otro idioma activo, incluido el submenú en móvil.

Resultado esperado: el enlace visible abre el destino correcto en cada idioma y no produce 404 ni redirecciones inesperadas.

D · Crear un formulario y ponerlo en una página
  1. Abre Formularios Dinámicos → Nuevo Formulario y define una clave corta y estable, por ejemplo contact.
  2. Activa el formulario y decide si requiere CAPTCHA, email de notificación y respuesta automática.
  3. Completa el nombre, botón, descripción y mensajes en ES; copia o traduce a EN y a los demás idiomas activos.
  4. En el constructor agrega los campos. Usa una clave email si habrá respuesta automática.
  5. En cada campo define tipo, obligatorio, activo, etiqueta, placeholder, ayuda y opciones traducidas cuando aplique.
  6. Guarda el formulario y confirma que aparezca activo en la lista.
  7. En una página agrega el bloque form_embed y selecciona la clave del formulario.
  8. Prueba validaciones, CAPTCHA, mensaje de éxito y recepción del email sin guardar datos reales innecesarios.

Resultado esperado: el formulario se ve en la página, valida los campos y el envío aparece en Envíos.

E · Subir y reutilizar un archivo
  1. Abre Archivos y elige un archivo con un nombre reconocible.
  2. Sube el archivo y espera la confirmación; no cierres la pantalla durante el procesamiento de variantes.
  3. Abre Ver y, en el detalle, completa texto alternativo, pie de foto y crédito. La pantalla de carga no solicita esos datos.
  4. Revisa Usado en y las variantes antes de reutilizarlo.
  5. Desde una imagen o bloque multimedia, elige Biblioteca y selecciona el archivo.

Resultado esperado: el contenido usa la referencia central del archivo y no una copia duplicada sin metadata.

F · Dar acceso a un editor
  1. Abre Usuarios → Crear usuario o edita una cuenta existente.
  2. Completa nombre, apellido y email; confirma que el correo sea correcto.
  3. Asigna cms-editor para trabajo editorial acotado, o cms-admin si necesita administrar estructura CMS.
  4. Evita admin y superadmin salvo que la persona deba administrar usuarios, IAM o toda la plataforma.
  5. Guarda, pide al usuario iniciar sesión y comprueba que solo vea los módulos necesarios.

Resultado esperado: la persona puede realizar su trabajo sin recibir permisos innecesarios.

G · Corregir una URL antigua
  1. Confirma cuál era la ruta anterior y cuál es la URL nueva.
  2. Abre Redirecciones → Nueva Redirección.
  3. Escribe la ruta antigua empezando por /; usa 301 si el cambio es permanente y 302 si es temporal.
  4. Activa la redirección solo después de revisar que el destino exista.
  5. Prueba la ruta antigua, la nueva y una ruta distinta para comprobar que no se creó un bucle.

Resultado esperado: la ruta antigua lleva al destino correcto sin encadenar varias redirecciones.

Publicación y revisión

Publicar es el último paso de una cadena. No es lo mismo guardar, activar, programar y hacer visible.

1Borrador

El contenido está guardado y todavía no debe ser público.

2Revisión

Otra persona comprueba texto, enlaces, imágenes, SEO y permisos.

3Idiomas

Se completan traducciones y se revisa la auditoría.

4Vista previa

Se comprueba la composición antes de hacerla pública.

5Publicar / programar

Se define cuándo debe verse en el sitio público.

Antes de pulsar Publicar ahora

Qué hacer después

  1. Abre la URL pública en una pestaña separada y prueba el flujo como visitante.
  2. Comprueba escritorio y móvil, navegación, imágenes, idioma y formularios.
  3. Si el sitio sigue mostrando una versión anterior, revisa caché/estado del servicio y vuelve a verificar; no publiques varias copias por impaciencia.
  4. Consulta Auditoría para dejar evidencia del cambio.
Sobre volver atrás
En el recorrido del Admin no aparece un botón general de “rollback”. Para revertir un cambio, vuelve a introducir valores conocidos, guarda y publica de nuevo; si el cambio es grave, coordina la restauración desde el respaldo o procedimiento de operación del proyecto.

Qué sí y qué no puede recuperar el Admin

El Admin sí ayuda a

  • Editar un registro conservando su identificador.
  • Volver un contenido a borrador o archivarlo.
  • Restaurar un archivo si la instalación ofrece esa acción.
  • Consultar cambios en Auditoría.
  • Corregir traducciones, enlaces, estados y permisos.

El Admin no reemplaza

  • Una copia de seguridad completa.
  • Un rollback de base de datos o despliegue.
  • La recuperación de una API key que ya fue expuesta.
  • La reconstrucción de un archivo eliminado definitivamente.
  • La investigación de un problema de infraestructura fuera del panel.
Registra la recuperación
Anota fecha, módulo, registro afectado, estado anterior, corrección y verificación final. Esto permite que otra persona entienda qué ocurrió sin repetir el incidente.

Preguntas frecuentes

Respuestas cortas para las dudas que suelen bloquear a una persona que usa el panel por primera vez.

¿Por qué no veo un módulo?
La barra lateral depende del permiso de lectura y del rol. Confirma el usuario, vuelve a iniciar sesión y pide revisar read para ese recurso. No significa automáticamente que el módulo esté roto.
¿Por qué una lista no muestra resultados?
Limpia la búsqueda y los filtros, revisa la pestaña de estado y confirma el idioma. Una lista vacía puede ser normal si todavía no existe el primer registro.
¿Cuál es la diferencia entre activo y publicado?
Activo suele habilitar un recurso o configuración para que pueda usarse. Publicado describe el estado editorial de una página o entrada. Un formulario puede estar activo y aun así no aparecer si ninguna página lo inserta.
¿Título y slug son lo mismo?
No. El título es texto para personas; el slug es el identificador legible de la URL. Puedes cambiar el título sin cambiar la URL, pero cambiar el slug requiere revisar menús, enlaces y redirecciones.
¿Qué diferencia hay entre colección y entrada?
Una colección define el tipo de contenido, como Noticias o Portafolio. Una entrada es un registro concreto dentro de esa colección.
¿Qué diferencia hay entre página y bloque?
La página es el documento y su URL; los bloques son las piezas que componen su contenido visual. Un tipo de bloque es la plantilla de campos y una instancia de bloque es el contenido concreto.
¿Por qué un elemento de menú muestra 404?
El destino puede estar borrador, archivado, tener un slug cambiado, faltar en el idioma activo o apuntar a una URL manual incorrecta. Abre el destino directamente, corrígelo y vuelve a probar el menú.
¿Por qué una traducción no aparece en público?
Revisa que el idioma esté activo, que el contenido traducido esté guardado y que la URL corresponda a ese idioma. Comprueba el fallback: puede estar mostrando el idioma base cuando falta la traducción.
¿Qué hace Auto-traducir?
Genera o propone valores para los idiomas disponibles. No revisa tono, nombres propios, SEO, enlaces ni exactitud comercial. Siempre requiere revisión humana y auditoría posterior.
¿Por qué no aparece un bloque en el selector?
Puede estar inactivo, no soportar el propietario actual, no permitir ese contenedor o necesitar una actualización de caché. Revisa Tipos de Bloque y el soporte para páginas/entradas.
¿Por qué un formulario no envía?
Comprueba que esté activo, que la página use form_embed con la clave correcta, que los campos obligatorios tengan claves válidas, que CAPTCHA esté configurado y que el email de notificación sea correcto. Luego prueba con datos ficticios y mira Envíos.
¿Qué rol debería asignar?
Empieza por la tarea, no por el nombre de la persona: cms-editor para edición editorial, cms-admin para estructura CMS, admin para operación general y superadmin solo para responsabilidades IAM. Confirma siempre la matriz real.
¿Cuándo uso 301 y cuándo 302?
Usa 301 cuando la ruta cambió de forma permanente. Usa 302 para una sustitución temporal o una prueba. En ambos casos evita bucles.
¿Puedo borrar un archivo?
Solo después de comprobar Usado en, variantes y necesidad de recuperación. Si hay duda, desactívalo o déjalo en papelera según el flujo de la instalación y consulta al responsable.
¿Por qué el sitio público sigue mostrando lo antiguo?
El contenido puede seguir en borrador, estar programado para otra fecha, estar en otro idioma o estar detrás de caché. Verifica primero estado, fecha, URL, idioma y salud de los servicios.

Configuración

Estas pantallas afectan el comportamiento global del sitio y deben cambiarse con control.

Tipos de Bloque

El catálogo contiene clave, nombre, categoría, descripción, icono y estado. Refrescar caché vuelve a preparar el catálogo. Crear o editar un tipo permite definir fuente de contenido, esquema JSON, campos traducibles, campos de configuración, soporte para páginas/entradas, contenedor y tipos hijos.

No cambies un block_key usado por contenido existente sin planificar la migración: los bloques guardan esa referencia.

Redirecciones

En Nueva Redirección define Ruta anterior (debe comenzar por /), Nueva URL, nota, tipo 301 o 302 y estado activo. La lista permite exportar CSV; también ofrece importar CSV. Valida primero en un entorno de prueba para no crear bucles.

Idiomas

La lista muestra código, nombre, nombre nativo, predeterminado y activo. En crear/editar define código, nombre, nombre nativo, si será predeterminado, si estará activo y el Idioma de reserva. Usa Establecer como predeterminado solo cuando el cambio sea intencional; Reordenar cambia el orden de presentación.

Auditoría de Traducciones

Es el centro de revisión. Filtra por búsqueda, idioma, recurso y estado. Audita páginas, menús, colecciones, entradas, categorías, etiquetas, formularios, campos, bloques, ítems de menú y configuración. Traducir abre el editor exacto, normalmente con el idioma pendiente enfocado; vuelve aquí y repite hasta limpiar los faltantes.

Identidad del sitio

Es la pantalla para nombre, título, tagline, descripción, datos de contacto, mensajes de email, copyright, analytics, redes sociales, reCAPTCHA y diseño de menús de pie. Las pestañas de los idiomas activos editan valores localizados; Traducir todos los idiomas y Auto-traducir ayudan, pero deben revisarse. En Activos de marca selecciona o cambia logo y favicon desde la biblioteca, luego pulsa Guardar.

Configuración

Es una lista filtrable por clave, grupo y página. Cada fila muestra valor, tipo, grupo, si es traducible, traducciones y descripción. Usa Ver para consultar y Editar para cambiar; crea una configuración nueva solo si el equipo conoce cómo la consumirá el sitio.

Mantenimiento operativo

Un sitio sano se mantiene con revisiones pequeñas y frecuentes, no solo cuando aparece un error.

Cada día de trabajo

  • Revisar Estado del Sistema al entrar.
  • Trabajar en borrador y limpiar pendientes de traducción.
  • Comprobar que el último contenido tenga imagen, alt text y URL.
  • Cerrar sesión al terminar.

Cada semana

  • Revisar Auditoría y actividad reciente.
  • Revisar Analytics y páginas con tráfico inesperado.
  • Revisar Envíos nuevos, spam y archivados.
  • Buscar archivos duplicados o sin uso antes de acumularlos.

Cada mes o ante cambios

  • Revisar usuarios, roles y API keys.
  • Rotar claves que ya no sean necesarias.
  • Revisar redirecciones, idiomas y configuraciones globales.
  • Probar una URL de cada menú y formulario.

Qué no está dentro del Admin

En el recorrido del panel no aparece una pantalla general de copias de seguridad/restauración. Los respaldos, despliegues, variables secretas y recuperación completa deben seguir el procedimiento externo del proyecto. El Admin sirve para operar contenido y accesos; no reemplaza la operación de infraestructura.

Después de un cambio global
Si cambias un idioma, identidad del sitio, configuración, tipo de bloque o permisos, registra qué cambió, quién lo hizo y cómo se verificó en el sitio público.

Mantenimiento de esta guía

La guía también necesita una revisión cuando cambia el producto. El siguiente registro deja claro qué se observó y cuándo hay que volver a recorrer el Admin.

Quién mantiene el manual

La persona responsable del Admin o del onboarding debe actualizar textos, capturas, rutas, matriz de roles y fecha de revisión. Cada cambio debe conservar el mismo nivel de detalle: qué hace, cómo se usa, qué valida y qué riesgo tiene.

Cómo verificar una actualización

  1. Recorrer el módulo en la instancia de prueba.
  2. Capturar listado y formulario.
  3. Comparar opciones y mensajes con esta guía.
  4. Probar un flujo sin guardar y otro de extremo a extremo.
  5. Actualizar versión, fecha y checklist.

Qué hacer y qué evitar

La administración es poderosa porque varias acciones tienen efecto inmediato sobre el sitio o los permisos.

Sí hacer

  • Trabajar en borrador y programar cuando el contenido esté revisado.
  • Completar ES y revisar EN y los demás idiomas activos en la auditoría.
  • Usar la biblioteca de archivos y completar alt text.
  • Confirmar el detalle del elemento antes de editar o eliminar.
  • Revisar Usado en antes de retirar un archivo o formulario.
  • Guardar la matriz de permisos y cerrar sesión al terminar.

No hacer

  • No mezclar localhost y 127.0.0.1 en el admin.
  • No usar Eliminar definitivamente salvo que el archivo esté verificado como prescindible.
  • No asignar superadmin o iam.superadmin-access por comodidad.
  • No publicar sin revisar slugs, enlaces, SEO y traducciones.
  • No compartir API keys ni subirlas al repositorio.
